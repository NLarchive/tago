# TAGO v3.7 review and v3.8 plan

*Review date: 2026-11-23. Sources: `tago_v37_agent_graph_lab.ipynb` / `.py` (132 cells, about 2,060 lines), `PROJECT_SPEC.md`, the legacy notebooks v3.1–v3.6, and the only real run artifact, `results/v37_colab_t4_qwen2.5-7b/` (Colab T4, qwen2.5:7b).*

## 1. What the project is

TAGO is an evaluation lab for tool-using LLM agents. A generic, bounded state graph (`start → infer → validate → tool → infer … → finish | repair → quarantine | failed`) drives one model through ten fictional enterprise workflows (E01–E10). The model can learn facts only through sandboxed tools. It may only propose actions, and every human-gated action ends as `PENDING_APPROVAL`. A hidden oracle computes the correct answer from private case facts, and a rubric grades correctness, provenance, literal citations and the approval gate.

**Acronym.** "TAGO" is not expanded anywhere in v3.1–v3.7. It stands for **T4 Agent Graph Orchestrator** (T4 = the Colab GPU class the lab is sized for).

## 2. Strengths worth keeping

- The evaluation design is sound. The oracle is independent of the worker's tool output, invalid synthetic data is never scored as a model failure, and the notebook says plainly what was and was not executed.
- Safety is built into the design: no external writes, a fixed sandbox browser, and an arithmetic checker that walks the syntax tree instead of calling `eval`.
- Token preflight uses the real chat template and refuses to call rather than truncate.
- There is a clean separation of domain packs from the generic runner, and a 26-test offline contract suite.

### Root causes

1. **The output schema did not constrain tool arguments.** `ToolRequest.arguments` was `dict[str, Any]`, so the JSON schema Ollama compiled into its grammar accepted any object, including `{}`. Even though decoding was grammar-constrained, the grammar allowed every one of the failing calls.
2. **The repair loop could not repair.** At temperature 0 with a fixed seed, an unchanged prompt gives an unchanged answer. The feedback text (`Arguments must match documented nonempty string fields`) was the same each time and did not name the expected key. The recorded `prompt_hash` values are identical for calls 6/7, 9/10 and 12/13, so the model received the same prompt and returned the same call until the run was quarantined.
3. **No progress signal.** Nothing told the model that `ticket_read` had already succeeded or that `retrieve` was still needed, and nothing stopped identical calls.
4. **The cold start almost timed out.** The first call took 119.1 s against a 120 s request timeout. One more second would have produced a `FAILED` run caused by infrastructure, not the model.
5. **The golden gate hid everything downstream.** `REQUIRE_GOLDEN_PASS=True` blocked the synthetic sweep, so no clean or noisy case was ever generated, audited or graded.

## 4. Critique: issues found and their v3.8 status

| ID | Severity | Issue | v3.8 status |
|---|---|---|---|
| I-01 | Critical | Tool arguments unconstrained in the output schema | **Fixed**: per-pack union schema with exact argument keys and finding keys (`build_step_schema`) |
| I-02 | High | Repair feedback does not say what was expected; deterministic retries are identical | **Fixed**: feedback names expected and received keys and echoes the rejected step |
| I-03 | High | No duplicate-call or loop guard | **Fixed**: duplicate calls refused with a pointer to the existing observation, plus an optional `progress` hint |
| I-04 | High | Cold-start latency ≈ timeout | **Fixed**: explicit `warmup()` (900 s), `keep_alive`, 180 s request timeout |
| I-05 | Medium | Golden failure blocks all synthetic data | **Fixed**: `REQUIRE_GOLDEN_PASS=False` by default |
| I-06 | Medium | Observations sent twice (`data` and `content`), so the prompt grows quickly | **Fixed**: `content` only |
| I-07 | Low | One repair budget for the whole run punishes long workflows | **Changed**: consecutive-repair limit, reset after a successful tool call. The step budget stays the global bound |
| I-08 | High (publication) | A 2,000-line notebook and a `.py` copy maintained by hand; tests run only inside the notebook; no CI, packaging, README or licence | **Fixed**: `tago/` package is the single source; the notebook is generated (`tools/build_notebook.py --check`); pytest, CI, `pyproject.toml`, README |
| I-09 | Medium | Ring violations: application imported the sandbox host and the arithmetic tool | **Fixed**: ports-level registries, arithmetic rule moved to domain, AST architecture test |
| I-10 | Medium | One model profile only; no way to compare with API models | **Added**: five Ollama profiles, OpenAI-compatible and Anthropic backends, model matrix. *Not measured yet* |
| I-11 | Medium | Failures reported only as pass/fail | **Added**: failure taxonomy, duplicate-call count, repair log, analysis CLI |
| I-12 | Medium | `alert_read` returns `sensitive_asset`, so E09's `graph_walk` is required by provenance rules but not needed to know the answer | **Deferred** to v3.9. Changing it now would break comparability with v3.7 (task V39-01) |
| I-13 | Medium | Citation check accepts any substring of at least 2 characters (for example `":`), so grounding can be gamed | **Deferred** to v3.9: require the quote to contain the finding value (task V39-02) |
| I-14 | High (validity) | Three golden cases and N=1 synthetic per mode cannot support any statistical claim | **Planned**: results campaign with ≥ 20 cases per workflow and mode (results graph, task 6) |
| I-15 | Medium | Generator, auditor and worker share one model, so their errors are correlated | Documented. The matrix allows a different auditor model (task V39-03) |
| I-16 | Low | OpenAI `strict` structured outputs not used, so API schema adherence is not grammar-guaranteed | Documented; outputs are validated locally (task V39-04) |
| I-17 | Low | No human-approval resume path; `PENDING_APPROVAL` is terminal | Documented limitation (task V39-05) |
| I-18 | Low | `PROJECT_SPEC.md` suggests exposing functions over HTTP | Not adopted. A CLI gateway (`python -m tago`) fits an evaluation lab better |

### Assessment of an external review of this run

Each statement was checked against the committed artifacts.

| Claim | Assessment |
|---|---|
| Same model generates, audits and orchestrates, so errors correlate | **True by design and documented (I-15).** The run shows it: the auditor passed a case whose id did not match the tool contract (N-08). A different-family auditor is now one setting (`TAGO_AUDITOR_MODEL`). |
| Prompt context growth degrades small models | **Not supported at this scale.** Prompt size ranged from 1,140 to at most 1,569 tokens across the golden runs, far from the 8,192 window. It may matter for long workflows; added as backlog item V39-07 with a measurement plan. |
| Exact-substring citations are brittle | **Partly true.** One real case of a paraphrased quote (N-05). The rule is the point of the benchmark (provenance), so v3.8.2 keeps it case-sensitive but ignores whitespace and tells the model exactly what to copy. A semantic matcher would weaken the oracle. |
| Failure modes `duplicate_tool_loop`, `premature_final`, `wrong_finding` were observed | **Not in this run.** The observed categories were `output_schema` ×3 (golden) and `wrong_reference` ×3 (synthetic). Those three names exist in the taxonomy, but no record contains them, and E03's arithmetic was correct. The breakdown reads as generic, not derived from `model_calls.json`. |
| Model sizing for a 15 GB T4 | **Directionally sound, partly unverified.** Weight sizes agree with the Ollama pages for granite4.1:8b (5.3 GB), ministral-3:8b (6.0 GB), gemma4:12b (7.6 GB). The 8K KV-cache headroom argument is reasonable; the 12–13 GB ceiling is a rule of thumb, not measured here. |
| Thinking models may exhaust `output_tokens=1600` | **Plausible and handled**: hybrid profiles get `output_tokens=3000`, and `think` is not sent unless `TAGO_THINK=off`. Unmeasured. |
| `think:false` can disable `format` on some builds | Reported by others; **not tested here**. That is why the default never sends it, and why the first golden pass of a thinking model is a gate before more spending. |
| Registered tags and Hugging Face ids in the review | Tags `ministral-3:8b/14b`, `granite4.1:8b`, `gemma4:12b` were found on ollama.com; `qwen3.5:9b` is listed in derivative pages. **The tokenizer repo ids were not opened.** They are registered as `candidate`; a wrong id fails preflight with `ContextError` and is recorded, never guessed around. |
| `qwen3.8:27b`, `qwen3.6:27b` mentioned as 27B models | Not verified; not registered. |

**Model plan (T4, 15 GB).** Run order that keeps variables separate: (1) re-run `qwen2.5:7b` alone to measure v3.8.2; (2) the ablation ladder on the same model; (3) `qwen2.5:14b` as the size control within one family; (4) `granite4.1:8b`, `ministral-3:14b` as non-thinking instruct families; (5) `gemma4:12b`, `qwen3.5:9b` hybrid-thinking, golden-first. `gpt-oss:20b` and `deepseek-r1` are intentionally not registered.
